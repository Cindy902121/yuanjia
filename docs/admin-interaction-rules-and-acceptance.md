# Admin 共用互動規則與驗收案例

版本：v1.2｜整理日期：2026-09-09｜實作盤點基準：`main`（本次驗收基準）

用途：統一 Admin 導覽狀態、詳情互動、日期口徑與資料更新的開發和驗收依據。

**文件狀態：規則已接入並合併至 `main`，行為驗收分為通過、失敗與受阻。** 本文件將已確認方向具體化；「本版補定」表示這次為消除歧義所選擇的建議預設，不代表先前已逐條獲得使用者確認。下方只記錄本次實際執行的證據，未具備本地／隔離服務前提的案例維持「受阻」，不能因靜態測試或文件完成而視為通過。

## 1. 依據、範圍與固定邊界

- [路由與權限規格](./route-and-permission-spec.md)：角色、路由、合法操作的優先依據。
- [Auth 授權矩陣](./auth-authorization-matrix.md)：伺服器授權依據。
- [品牌設計規範](../../設計分析與改善方案/design.md)：字體、品牌色、焦點、間距與響應式依據。
- 本次對話已確認：B2B 待辦優先、B2C 展示訂單為次要入口、待辦與分析日期分開、資料失敗不可當作零。
- 程式依據：`src/app/admin/`、`src/app/api/admin/`、`src/lib/analytics/report.ts`。本文件規定目標行為；現有程式差異見第 8 節。

適用 `/admin`、`/admin/business`、既有商品編輯頁，以及由它們呼叫的管理 API。詢價詳情使用既有管理路由的 query，不新增獨立路由。

`admin` 可使用全部既有管理模組；`business_staff` 只使用 B2B 商品與詢價，不新增其分析、企業會員或帳號管理權限。B2C 訂單始終稱「展示訂單」，不可呈現為真實营收或付款／配送成果。

本文件不授權 production 資料操作、migration、commit、push 或部署。狀態變更測試僅在本機／明確隔離環境執行。

## 2. 導覽與網址狀態

### 2.1 共用規則

| ID | 規則 |
|---|---|
| NAV-01 | 網址為「已套用」模組、篩選、排序、頁碼、詳情 ID 與報表日期的唯一來源。React 可保存尚未套用的輸入，不得有第二份互相矛盾的已套用状態。 |
| NAV-02 | 沒有 `tab` 時，`/admin` 顯示 `overview`；`/admin/business` 顯示 `b2b-products`。瀏覽器返回到無 `tab` 網址也套用此規則。 |
| NAV-03 | 不存在／無權使用的 `tab` 回到該路由合法預設模組，顯示「已返回可使用的管理頁面」，以 replace 修正網址。進入未授權路由與 API 仍按既有伺服器授權處理，不能靠隱藏選單取代。 |
| NAV-04 | 點擊側欄、套用篩選／日期、切換頁碼、開啟詳情使用 push；清理不合法參數與補預設值使用 replace。不得每輸入一個字就增加歷史紀錄。 |
| NAV-05 | 搜尋與自訂日期先保留為草稿；按「套用」或送出表單才查詢。清除篩選一次恢復該模組預設值。 |
| NAV-06 | 改搜尋、篩選或排序，重設該清單頁碼為 1、清除詳情 ID 與批次選取；翻頁也清除批次選取。批次選取僅作用於目前頁面，不隱含選取全部搜尋結果。 |
| NAV-07 | 切換模組移除原清單專屬 query，保留有效的分析日期；返回歷史紀錄可恢復原模組 query。日期不作為待辦查詢條件。 |
| NAV-08 | 同一視窗從清單開啟詳情時，記錄完整來源網址、捲動位置與觸發項目。返回時恢復來源清單與焦點；若項目已移出篩選結果，焦點改放清單標題並說明原因。直接開啟詳情時不依赖 history 存在，使用明確的清單返回網址。 |
| NAV-09 | 缺省參數採表列預設值；無效狀態／排序、重複的單值參數、格式錯誤頁碼，UI 顯示提示並 replace 為預設。API 對不合法輸入回 400，不默默擴大查詢。空搜尋視為未篩選。 |
| NAV-10 | URL 與返回目的地只允許同站且角色可使用的管理路由。不得把密碼、聯絡資料或整份表單放入 query／history／持久儲存；只儲存必要的識別碼與視圖條件。 |

### 2.2 Query 契約（本版補定）

| 參數 | 適用 | 預設／限制 | 對應行為 |
|---|---|---|---|
| `tab` | 管理路由 | 既有合法模組，依角色限制 | 同時驅動畫面與選取導覽 |
| `queue` | 總覽 | `new`；另允許 `processing` | 只切換總覽待辦列 |
| `rfq_status` | 詢價清單 | `new`；允許 `all/processing/closed` | `all` 不送 API status |
| `rfq_sort` | 詢價清單 | `oldest`；另允許 `newest` | 同時間以 ID 升冪穩定排序 |
| `rfq_page` | 詢價清單 | 正整數，預設 1，每頁 25 | API `page`／`page_size=25` |
| `rfq_id` | 詢價詳情 | UUID | 詳情以 ID 查詢，不受來源狀態／頁碼限制 |
| `product_status` | B2B 商品 | `all`；另允許既有四種商品狀態 | 狀態篩選 |
| `product_q` | B2B 商品 | 空值 | 商品名稱、代碼、品牌、分類搜尋 |
| `missing_images` | B2B 商品 | 缺省／`false`；`true` 啟用 | 與商品狀態、搜尋以 AND 組合 |
| `product_page` | B2B 商品 | 正整數，預設 1，每頁 25 | `updated_at` 降冪、ID 升冪 |
| `date_from/date_to` | 總覽、分析報表 | 同第 4 節，成對存在 | 跨兩頁延續相同期間 |

超過最後一頁時，以服務端總數重算最後有效頁（最少為 1），replace 後讀取一次並提示「資料已更新，已調整頁碼」。總数必須來自精確統計，不得使用目前載入列數。完整報表的其他既有維度篩選應以 API 同名 query 保存；匯出用途與備註不是篩選條件。

## 3. 詳情與修改互動

### 3.1 詢價詳情（本版補定）

採同一路由內的完整詳情內容，例如 `/admin?tab=b2b-rfqs&rfq_status=new&rfq_sort=oldest&rfq_page=2&rfq_id=<UUID>`。桌面和手機都以詳情取代列表主內容，保留管理導覽；不以 modal 承擔主要導覽。

| ID | 規則 |
|---|---|
| DET-01 | 每次進入詳情按 ID 重新讀取。顯示案件識別、公司、建立時間、狀態、商品、數量／單位、規格／包裝快照與備註；不能只使用列表摘要。未知商品以文字說明，不隱藏原始需求快照。 |
| DET-02 | 詳情成功顯示後焦點移至詳情標題；清楚提供「返回詢價清單」。Escape 不離開這種完整頁面。離開／返回遵循 NAV-08。 |
| DET-03 | 無效 ID 顯示「詢價連結格式不正確」；合法 ID 無資料顯示「找不到此詢價」；403 顯示無權限且不顯示案件資料；網路／503 提供局部重試。均保留合法返回入口。 |
| DET-04 | 初版以明確按鈕直接要求狀態變更，不保留未儲存的下拉選擇。`new` 可「開始處理」或「結案」；`processing` 可「標記為新詢價」或「結案」；`closed` 可「標記為新詢價」或「重新處理」。保留既有 API 可接受的狀態能力，不新增業務限制。 |
| DET-05 | 「結案」及從已結案重新開啟需確認，內容包含案件與目標狀態；取消不送請求。送出中禁止同案件重複動作並顯示「更新中」。成功按服務端結果顯示新狀態，失敗保留原值及操作入口。 |
| DET-06 | 成功後停留在詳情，提示「詢價已更新為……」。即使案件已不符合來源篩選也不自動關閉；返回後列表移除該案件，且顯示已移出的原因。 |

### 3.2 商品／會員長表單與同時修改

| ID | 規則 |
|---|---|
| DET-07 | 商品內容沿用既有編輯頁。長表單採「儲存變更／取消」；欄位與最後服務端已儲存值不同才算未儲存。切換模組、返回、關閉分頁須提醒；取消離開保留輸入，確認捨棄才離開。瀏覽器離站使用其原生提醒，不保證自訂文字。 |
| DET-08 | 驗證錯誤保留輸入；多欄錯誤聚焦摘要並連到欄位，單一錯誤聚焦該欄位。成功提示不搶走焦點。401/403 不持續重試寫入；密碼不得為恢復表單而寫入持久儲存。 |
| DET-09 | 兩人同時修改採樂觀併發檢查：提交原始 `updated_at` 或等效版本條件，服務端原子比對後才寫入。衝突回 409，顯示「此資料已被更新，請重新讀取後再操作」，不自動覆蓋或重送。長表單保留本次輸入供人工比對，但下一次寫入需以新版本重新確認。 |

截至本次 `main` 驗收基準，程式已對詢價、B2B／B2C 商品、企業會員與展示訂單接入 `updated_at` 原子比對；商品長表單也會在 409 後保留本次輸入並要求重新讀取。其他尚未納入本次寫入的表單仍需先確認 schema 與替代版本機制；其併發案例標記「受阻」，不得當作通過，也不因此自動執行 migration。

## 4. 日期與統計口徑

| ID | 規則 |
|---|---|
| DAT-01 | 顯示與日期邊界固定 `Asia/Taipei`，與操作者裝置時區無關。UI 起迄日皆包含；查詢為起日 00:00（含）至迄日次日 00:00（不含），再轉 UTC。 |
| DAT-02 | 無日期時，總覽和完整報表皆使用最近 7 個完整日，到昨天為止；寫成明確日期 query。跨頁、重新整理及返回都沿用它，不因午夜經過偷偷改變。按快捷日期按鈕時才依當下台北日期重算。 |
| DAT-03 | 選今天合法，但顯示「今天的資料尚未結束」。未來日期、無效曆日、缺一個日期、起日大於迄日，前後端都拒絕；UI 保留輸入並提示，不發新查詢。直接開啟無效 query 顯示修正日期表單，不顯示其他期間數字或默默擴大範圍。 |
| DAT-04 | 最多往前 24 個曆月，按迄日減 24 月算最早起日；不存在的日落在該月最後一天。起日等於界線合法，再早一天不合法。前後端使用同一函式／測例。 |
| DAT-05 | 前期為緊接本期之前、相同包含日數的期間。含今天時不顯示前期差值或成長率，保留本期數字與未結束提示。前期為零時百分比顯示「—（前期為 0）」而非無限大；沒有資料與數字 0 分別處理。 |
| DAT-06 | 1–90 天按日、91–365 天按週、366 天以上按月。週一為週起點、每月 1 日為月起點，均按台北時間。首尾不足完整週／月時，標出實際涵蓋起迄日與「部分期間」。 |
| DAT-07 | 資料成功回應後，標題、摘要、圖表、表格及匯出皆使用同一組服務端有效期間和篩選。輸入草稿不改動既有圖表標題。匯出不使用尚未套用的日期。 |
| DAT-08 | 活躍企業是期間內有合格活動的去重企業數；不等於啟用會員數，不加總每日去重數。詢價單數依期間內建立的詢價單去重，非送出事件次數。狀態或金額不能推導成付款／營收。 |
| DAT-09 | 待辦是目前狀態，與任何分析日期無關。無圖片數可與各商品狀態重疊；不可把它和四個狀態相加當商品總量。 |
| DAT-10 | 趨勢按時間排序；已確認覆蓋且無活動的區間補 0，未知／讀取失敗區間維持缺資料，不補 0。日／週／月用實際時間位置；提供文字摘要與同口徑資料表。 |

例：將時鐘固定為台北 `2026-09-06 12:00`，預設為 `2026-08-30` 至 `2026-09-05`；UTC 查詢邊界為 `[2026-08-29T16:00:00Z, 2026-09-05T16:00:00Z)`；前期為 `2026-08-23` 至 `2026-08-29`。

## 5. 資料讀取、更新及錯誤規則

### 5.1 觸發與狀態（本版補定）

| ID | 規則 |
|---|---|
| UPD-01 | 初版在進入視圖、套用新條件、手動更新及操作成功時讀取。無定時輪詢，不因切回分頁自動改動資料。距最後成功讀取超過 5 分鐘顯示「資料可能已變更，可重新整理」；此標記不代表資料一定過期。 |
| UPD-02 | 全頁「重新整理」只更新目前視圖依賴的資源；總覽更新待辦統計、待辦列與分析。保留 DOM、焦點、捲動與已套用條件，不卸載整個工作區。未儲存表單不因更新被覆蓋。 |
| UPD-03 | 首次讀取使用固定尺寸骨架；更新同條件保留旧資料並標示更新中；更換條件時不得把舊條件的列／數字放在新條件標題下。後到的舊請求不能覆蓋新結果，離開視圖取消不再需要的請求。 |
| UPD-04 | 每個資源獨立成功／失敗。有效 0 顯示 0，無值顯示 —；不可把 null、失敗、尚未載入當零。失敗且有同條件舊資料時顯示「更新失敗，顯示上次資料」，附其最後成功時間；首次失敗只顯示錯誤與重試。 |
| UPD-05 | 摘要部分值為 null 視為該指標失敗：只保留該值既有成功值並標示舊值，或無舊值時顯示 —；其他成功值可更新。時間不得暗示失敗項也剛更新。 |
| UPD-06 | 顯示「上次讀取成功」及台北完整日期時間（含年份）。這是應用程式讀取完成時間，不是所有資料的一致快照。總覽各區塊可有不同時間，不宣稱即時。 |
| UPD-07 | 操作成功以服務端回應為準，並使相关讀取失效，按下表重新取得。寫入成功、後續讀取失敗顯示「已儲存，但最新資料讀取失敗」，只重試讀取，不能重送寫入。 |
| UPD-08 | 401 清除敏感舊資料，提示登入逾時並提供同站合法返回路徑；403 清除無權資料並回合法模組或顯示無權限。重登入後不得自動重送操作。一般讀取錯誤可手動重試；不無限自動重試。 |
| UPD-09 | 寫入請求逾時／連線中斷但結果不確定時，顯示「操作結果尚未確認」，先重新讀取，不宣稱失敗或成功、不直接重送。伺服器若提供操作識別碼，重試須沿用它。 |

### 5.2 操作後同步矩陣

| 成功操作 | 需要重新驗證的資源 | 不應推導的結果 |
|---|---|---|
| 詢價狀態變更 | 目前詳情、對應詢價清單、待辦 new／processing 計數與待辦列 | 不自行增減期間詢價建立數 |
| 商品內容／發布狀態／圖片變更 | 商品詳情、商品清單、型錄狀態與無圖片計數 | 不把下架當成刪除 |
| B2C 展示訂單狀態變更 | 該展示訂單與清單 | 不改 B2B 計數或產生營收 |
| 企業會員新增／啟停 | 企業會員清單與已顯示的會員狀態摘要 | 不自行更動區間活躍企業數 |
| 切換分析日期／維度 | 分析摘要、趨勢、排行及匯出的已套用參數 | 不清除或縮小全部待辦 |

目前不可見資源可標記失效，下一次進入時讀取；不能只改某張卡片的數字來模擬成功。

## 6. 驗收資料與執行條件

下表的資料均為測試設計，不代表已建立或存在於正式環境。尚未有證據的案例仍標為「未執行」；需要登入、資料庫或儲存服務而本輪未提供隔離環境者標為「受阻」。

- 角色：一個 admin、一個 business_staff、一個非管理角色；分別測試登入、逾時及撤權。
- 詢價：至少 26 筆新詢價以跨過每頁 25 筆；另有處理中、已結案；兩筆同建立時間；一個有效但不存在的 UUID；一筆包含規格／包裝與備註快照。
- 商品：至少 26 筆，其中四種狀態皆有資料；缺圖片商品分布於至少兩個狀態；另備長名稱。
- 分析：固定時鐘，提供查詢上下界前後各一筆事件；同企業跨日活動、無活動日、未知區間；前期為零及非零資料。
- 失敗：以本機測試替身注入延遲、倒序回應、401、403、409、503、部分 null、寫入成功但讀取失敗。替身只能證明 UI／契約行為；精確總數、關聯缺圖與併發原子比對另需隔離服務實測。
- 介面：至少 390、768、1440 px；補 320 px 防溢出及 200% 縮放；鍵盤操作、焦點與 reduced-motion。

## 7. 驗收案例

每案記錄：執行日期、commit、環境、角色、尺寸、測試資料識別、實際結果、證據路徑及缺陷編號。結果僅用「未執行／通過／失敗／受阻」；有未滿足前提時記錄受阻，不能跳過後當作通過。

### 7.1 導覽
